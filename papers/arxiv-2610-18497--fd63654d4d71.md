###### Abstract

Tool-call judges evaluate argument values proposed by LLM agents. We
find that they accept a correct value less often when their input holds
no reference for it, that is, no text that says what the value should
be. This happens when the value is a default value from the function
schema that the user did not mention, when it has to be inferred, or
when the text it comes from was cut from the judge input. We call this
drop in acceptance the _derivation gap_. It appears across all seven
judges we evaluate, including System One models CLM and Jev. The gap is
not only a truncation artifact: correct default values have the largest
gap on a benchmark with no truncation. A controlled source-relocation
test shows that judges follow the reference in their input: they favor a
visible incorrect value over a correct value whose source is hidden. We
introduce DeRef (Derived Reference): a separate model reads the full
history without seeing the candidate and writes a reference for the
judge. Across three benchmarks, DeRef improves overall argument AUROC
for all judges tested. On the controlled test, it raises AUROC from
chance or below to between 98.40 and 99.59. The code is available at
[https://github.com/SarielMa/DeRef_release](https://github.com/SarielMa/DeRef_release)

## 1 Introduction

Figure 1: A correct argument on the History-only path, from CFB. (a) The

above both.

LLM agents act through tool calls. Wrong argument values are among the
most common errors in the tool calls of LLM agents, as in FC-RewardBench
(FCRB) (Agarwal et al., 2025). Agent pipelines therefore use judges to
check tool calls, as reward models (Agarwal et al., 2025; Li et al.,
2026b; Lin et al., 2026) and guards before execution (She et al., 2026).
Many checks operate at the argument level, from the BFCL benchmark to
ProvenanceGuard and ToolPRM (Patil et al., 2025; She et al., 2026; Lin
et al., 2026).

An argument judge sees the context and a proposed value, the
_candidate_, and decides whether it is right. But a correct value can
reach a call in several ways. It can be copied from visible text, taken
from an earlier tool return, filled in from a default that the function
schema specifies when the user does not mention the argument,
reformatted, or inferred. We call each way a _derivation path_. Figure 1
shows one such path: a correct vehicle ID taken from an earlier tool
return. The source of the ID is not visible to the judge, and all four
judges reject the value. Correct arguments that the input does not show
directly, like this ID, are accepted much less often than those it does.
We call this drop in acceptance rate the _derivation gap_.

The gap appears in all seven judges we study. Two are System One judges,
scoring models that return a probability rather than text (Kwok et al.,
2026; Almeida, 2026). Five are LLM judges from the Qwen, Llama, and
Mistral families (Yang et al., 2025; Qwen Team, 2026; Grattafiori et
al., 2024; Jiang et al., 2023). Scaling the judge from 4B to 27B
parameters does not remove the gap. The gap is also not only a matter of
missing information: on FCRB, where nothing is cut and each default is
shown, correct defaults have the largest gap.

Controlled tests point to one cause: a judge tends to accept a value
that is stated in its input, and to reject one that is not. It does not
reliably work out the correct value on its own. When we hide the source
of a correct value and leave a wrong value visible, AUROC falls to
chance or below for every judge tested. Giving the judge the full
history narrows the gap on values from earlier steps. It does not help
on values that match no span of the history. But when the input states
the expected value and the reason for it, judges accept values they
rejected before.

This points to a simple lever. If judges rely on a reference in their
input, we can supply one. DeRef (Derived Reference) asks a model to read
the full history without seeing the candidate. The model writes down the
expected value of each argument and where it comes from (Figure 1b). The
judge then scores the candidate with this reference in its input. In
Figure 1c, all four judges then accept the vehicle ID. Unlike judges
that write their own answer first, DeRef uses a separate model that
reads the full history.

Our contributions are as follows: (1) We identify a systematic
derivation gap across seven argument judges, from System One models to a
27B LLM. On ComplexFuncBench (CFB) and FinTrace it lies between 22.67
and 36.13 points for every judge, and on FCRB, with no truncation,
correct defaults have a gap between 14.40 and 50.51 points. (2) Through
controlled source relocation and reference substitution, we show that
judgments track explicit reference values in the input, even when these
favor an incorrect candidate over the correct one. (3) We introduce
DeRef, which derives a shared reference from the full history without
seeing the candidate. Without retraining or modifying the judges, it
improves overall argument AUROC for every judge tested, on all three
benchmarks. Averaged over tested judges, it is significantly above the
strongest prior method, RevisEval, on every benchmark. On the controlled
test with a hidden source, it lifts every judge from chance or below to
between 98.40 and 99.59.

## 2 Related Work

Judges for tool-calling. Benchmarks check calls against gold answers,
per argument (Patil et al., 2025) or per call (Zhong et al., 2025);
without gold answers, learned judges score whole calls (Agarwal et al.,
2025; Li et al., 2026b) or each argument as a step (Lin et al., 2026),
and benchmarks of such judges find that they tend to label steps as
correct and agree less with a reference as tasks get harder (Li et al.,
2026a; Fan et al., 2026b; Verma et al., 2026). Guards check calls before
they run: ProvenanceGuard finds evidence for each argument with the
value in hand (She et al., 2026), PACT and Agent-Sentry track where each
value came from (Fan et al., 2026a; Sequeira et al., 2026), and
TwinCheck repairs a flagged call from the trace (Dai and Huang, 2026).
Jev trails GPT-6 where the verdict has to be derived rather than read
off the text (Li et al., 2026c), and factuality metrics drop on
summaries that need deeper reasoning (Ramprasad and Wallace, 2025). To
our knowledge, none of these studies splits judge errors by derivation
path.

Reference-guided judging. Judges grade better with a reference, and
several have the judge write its own answer before seeing the candidate
(Zheng et al., 2023; Zeng et al., 2024; Li et al., 2026d; Zhou, 2026;
Andrade et al., 2026; Li et al., 2026e; Dhuliawala et al., 2024;
Raghavendra et al., 2026), or revise the candidate into one (Zhang et
al., 2025a); without a reference, judges agree less with experts and
credit wrong answers (Krumdick et al., 2025; Chalamalasetti and Vajjala,
2026), and with a wrong reference they reject answers that match it (Lee
et al., 2026). These judges write the reference from the question and
their own knowledge, which is often not enough for an argument judge,
whose expected value can sit in a tool return cut from its input, and a
reference the judge writes from its own input, as in LLMBar, stays below
DeRef (Section 5.2).

Correct content without support. A value without support in the context
is not always wrong: unsupported entities in summaries are often factual
(Cao et al., 2022), and RAG models often answer correctly when the
context is insufficient (Joren et al., 2025). Tool-call arguments make
this common, since a correct default, format change, or inferred value
has no matching span in the dialogue, and we measure how often judges
treat such values as errors. A source in the context can also go unused
(Modarressi et al., 2025; Kate et al., 2025). App. I discusses each line
of work in more detail.

## 3 The Derivation Gap

This section identifies the derivation gap and investigates its causes.
Section 3.1 defines the judging task and five derivation paths based on
how argument values relate to the history and the function schema.
Section 3.2 describes the benchmarks, judges, and judge input.
Section 3.3 measures differences in acceptance rates for correct values
across paths. Finally, Section 3.4 uses controlled tests to examine the
roles of missing information and explicit reference values, motivating
the introduction of DeRef in Section 4.

### 3.1 Argument-Level Judging and Derivation Paths

Task. An agent acts in a state with history $`H`$, which contains the
user turns, earlier tool calls, and their full returns. The agent
proposes a call to a function $`f`$ with $`k`$ arguments, where argument
$`i`$ has a name $`a_{i}`$ and a value $`v_{i}`$. An argument judge
checks one value at a time using a context $`X`$ built from $`H`$ and
the schema of $`f`$. $`X`$ does not need to contain all of $`H`$
(Section 3.2), so the text that determines a correct value can be
present in $`H`$ but absent from $`X`$. For each argument, the judge
returns a score $`s(v_{i}\mid a_{i},X)\in[0,1]`$, representing its
estimated probability that $`v_{i}`$ is correct.

Derivation paths. A correct value is not always a copy of text that the
judge can see. The derivation of a value $`v`$ can be described by a
_source_ $`e`$ and a _transformation_ $`t`$. The source is a span of
$`H`$ or a field of the function schema, such as a default. The
transformation copies the source, changes its format, or infers a new
value from it, so that $`t(e)=v`$. Each candidate value, whether right
or wrong, has a _derivation path_, determined by text-matching rules
(Appendix B). The paths capture how directly a value can be checked
against the dialogue shown to the judge. There are five path types, and
a value takes the first one that matches:

- •
  Visible: $`v`$ appears in the dialogue part of $`X`$, that is, the
  user turns, shown calls, and retained portions of their returns.
- •
  History-only: $`v`$ appears in $`H`$ but not in the dialogue part of
  $`X`$. The matching text was cut or dropped, as for the vehicle ID in
  Figure 1.
- •
  Format: $`v`$ matches a span of $`H`$ after a format-normalization
  step, such as converting two date expressions to the same form.
- •
  Default: $`v`$ matches a schema default or a “don’t care” value
  explicitly specified in the parameter description.
- •
  No-source: no match is found under the preceding rules.

Correctness is determined by the benchmark’s gold call, not by the
assigned path.

### 3.2 Benchmarks and Judges

Benchmarks. We use three tool-calling benchmarks, each with a gold call
at every step (Appendix A). FC-RewardBench (FCRB) gives 630 single-turn
requests, each with a correct call and a wrong call made by a real model
(Agarwal et al., 2025). ComplexFuncBench (CFB) has multi-step tasks with
long tool returns (Zhong et al., 2025). Its wrong calls come from the
trajectories of 30 models (AgentSuite, 2026), which gives 347 correct
and 644 wrong calls. FinTrace gives 2,334 golden calls for financial
queries (Cao et al., 2026) and 2,334 wrong calls, each made from a
golden call by changing one argument by rule.

Judges. We study seven judges (Appendix F). CLM (Kwok et al., 2026) and
Jev (Almeida, 2026) are System One judges, scoring models that return a
probability for a question about their input. The other five are LLM
judges: Qwen3 at 4B and 8B (Yang et al., 2025), Qwen3.8-27B (Qwen Team,
2026), Llama-3.1-8B-Instruct (Grattafiori et al., 2024), and
Mistral-7B-Instruct-v0.3 (Jiang et al., 2023). Their score is the
probability of “Yes” at the first output token, with thinking turned
off. Section 3.3 reports all seven judges. The controlled tests of
Section 3.4 and the main experiments of Section 5 use four of them: CLM,
Jev, Qwen3-8B, and Qwen3.8-27B.

Judge input. All judges see the same context $`X`$, which we call the
_Plain input_. We choose a truncated input on purpose: it keeps the last
few steps and cuts each return to 1,000 characters (Appendix A), which
is the input a judge sees in practice. Deployed agents stack cut context
the same way: the OpenAI Agents SDK provides a trimmer that cuts tool
outputs above 500 characters outside the last two turns, and Anthropic’s
guidance for long-running agents clears old tool results and compacts
earlier turns (OpenAI, 2026; Rajasekaran et al., 2025). FCRB requests
have no earlier calls, so nothing is cut there.

Statistics. All confidence intervals (CIs) are 95% bootstrap intervals
over 1,000 resamples of queries. A difference is called significant when
its CI excludes zero (Appendix C).

Metric. We compare how often a judge accepts correct values on different
derivation paths. A judge accepts a value when its score is above a
threshold. One fixed threshold for all judges is not fair, because
judges accept values at very different score levels. On CFB, for
example, Qwen3-8B accepts 80% of correct arguments at a score of 0.002,
and CLM at a score of 0.631. For each judge, dataset, and input, we
therefore set a threshold $`\tau`$ at which the judge accepts 80% of
correct arguments. Let $`A_{\tau}(p)`$ be the share of correct arguments
on path $`p`$ that the judge accepts at $`\tau`$. The _derivation gap_
of path $`p`$ is

```math
\mathrm{Gap}_{\tau}(p)=A_{\tau}(\textsc{Visible})-A_{\tau}(p). \tag{1}
```

A positive gap means that correct values on $`p`$ are accepted less
often than correct Visible values. We say that values on the Visible
path are _in view_ and that values on the other four paths are _out of
view_. We also report the gap of the out-of-view values pooled together.

The gap compares acceptance rates and not AUROC within a path. This is
because AUROC within a path can stay the same when a judge scores all
values on that path lower, right and wrong alike. A deployed judge
applies one threshold to every argument, so such a shift means more
false rejections on that path. Appendix C gives the rule for ties at
$`\tau`$. It also repeats the analysis with $`\tau`$ set to accept 70%
or 90%, where every CFB and FinTrace gap tested stays significant.

Results. Table 1 gives the gap for all seven judges. For each benchmark,
it reports the pooled out-of-view gap and the gap on the main
out-of-view path of that benchmark: Default on FCRB, History-only on
CFB, and No-source on FinTrace. On CFB and FinTrace, the out-of-view gap
is significant for every judge. On FCRB it is small, and defaults carry
the largest gap. Scale does not remove the gap, since Qwen3.8-27B, the
largest judge we run, has a significant out-of-view gap on all three
benchmarks, between 12.29 and 29.76 points.

Base rates. A gap could also arise from the base rate of a path, the
proportion of its values that are correct: if the base rate of a path is
lower, a judge would be right to trust its values less. On FCRB, 77% of
default values are correct, against 75% of values in view. On CFB, 83%
of history-only values are correct, against 82% in view. So base rates
do not explain the gap in either case. On FinTrace, only 45% of
no-source values are correct, against 97.5% in view, so this low base
rate may account for part of the gap.

Truncation is not the whole story. On CFB, truncation is an obvious
cause of the history-only gap, because it removes the text that these
values match. But it cannot be the only cause. On FCRB nothing is cut,
the default is written in the schema the judge reads, and correct
defaults still carry the largest gap of any path. A judge might
reasonably hesitate over a default that the user never mentioned. Yet
base rates do not explain this gap. This suggests a second explanation
besides missing information: the input has no explicit reference, that
is, no text that states what the value should be. Section 3.4 examines
both explanations with controlled tests.

### 3.4 Judges Follow the Reference

Figure 2: (a) Argument AUROC on FCRB-Relocate, with the source of the

its default input length of 2,048 tokens and is not given the full

Two explanations remain for a rejected correct value. The judge may lack
the information. Or it may have the information but no explicit
reference. The tests below examine these two explanations. They use the
four judges named in Section 3.2.

Test 1: judges prefer visible distractors when sources are hidden. If a
judge merely lacked information, hiding the source should push its score
toward uncertainty. Instead it follows the wrong value it can see. We
build FCRB-Relocate from 257 FCRB states. We move the value of one
argument from the user request into the return of an added earlier call.
The request now points to the right entry by one of its attributes. The
return lists eight entries, the correct one and seven distractors whose
values come from other FCRB samples. Each state has two versions that
differ only in the order of the entries. The correct entry comes second,
within the first 1,000 characters that the judge sees, or last, past
that cut. The first distractor stays in view in both versions. This
mirrors how history-only values arise in CFB (Appendix A). Burying the
source drops argument AUROC from between 91.89 and 99.88 to between
39.80 and 49.03 for all four judges (Figure 2a). Against the distractor
in view alone, AUROC is between 26.71 and 39.88, so all four judges rank
the wrong value they can see above the correct value that was cut. Given
the full history, Jev, Qwen3-8B, and Qwen3.8-27B recover, to between
98.39 and 99.86.

Test 2: restoring the information closes the gap only where a source was
cut. If truncation were the whole cause, the uncut history should close
the gap on every path. We give Jev, Qwen3-8B, and Qwen3.8-27B the full
history, with returns uncut and no window, up to each judge’s input
limit (Appendix A). On CFB, this narrows the gap on history-only values
by between 37.50 and 62.84 points, and for Qwen3.8-27B the remaining gap
is no longer significant (Table 17 in Appendix H). Argument AUROC on
these values rises by between 11.45 and 25.95 points. But on no-source
values it raises AUROC for none of the three judges, and it lowers it
for Jev by 2.83 points and for Qwen3-8B by 13.83 points (Table 18 in
Appendix H). Putting back only the one cut step that holds the source
has the same effect on FinTrace: it raises the scores of correct
history-only values for all four judges, against a placebo step of the
same kind (Appendix A). A reference also helps on top of the uncut
history (Section 5.3).

Test 3: the information can be in view and still not count. In FCRB the
default is written in the parameter description that the judge sees, and
nothing is cut, yet judges accept correct defaults less often than
correct values in view (Table 1). On the 142 of the 185 correct defaults
whose DeRef reference (Section 4) says that the default applies, a line
that restates the schema default and lists which related words appear in
the request changes acceptance by at most 6.18 points. The reference
itself, which writes out this derivation, raises it to between 73.02 and
88.06 (Figure 2b). This subset is chosen by the reference. Table 17 in
Appendix H reports all 185, with the same picture.

A matching reference lifts wrong values too. The three tests say that
judges need a reference. The last test shows that judges follow a
reference even when it supports a wrong value. On CFB, we add snippets
from the full history around each place where the candidate value
occurs, built by the snippet rule of Appendix G. Such snippets contain
the value by construction, so they agree with any candidate. On the 59
wrong history-only arguments, they raise the mean score for all four
judges, by between 14.28 and 39.39 points. At the 0.5 decision
threshold, CLM, Jev, and Qwen3-8B then accept between 28 and 49 of the
59, while Qwen3.8-27B accepts 2. On FinTrace-HC, which pairs for the
same argument a wrong value that appeared earlier in the history (H)
with one that did not (C), CLM, Jev, and Qwen3-8B score H higher than C
(Appendices A and G).

These tests show one pattern. A judge scores a value higher when a
reference in its input matches it, whether the value is right or wrong.
It does not reliably rebuild the derivation on its own, even from the
full history.

## 4 DeRef: Deriving the Reference

DeRef gives the judge a reference that is ready to use. It has two steps
(Figure 1b). A deriver model reads the full history $`H`$ and the
schema, with returns uncut and no window (Appendix F). The deriver sees
the function called at the step under judgment and its schema, but no
candidate value. For each argument it writes the expected value and its
source. If the history does not fix the value, it says so, and that
statement becomes the reference. Our deriver reads everything, so it can
name values whose source was cut from the judge input (Section 5.3).
Because the deriver never sees the candidate, the reference cannot echo
the value under test. The deriver writes one reference per argument of a
state, and all candidates at that state share it. We use Qwen3.8-27B
(Qwen Team, 2026) as the deriver for every judge, with thinking on
(Appendix G gives the prompt and Appendix F the settings). We insert the
reference into the judge input, after the history and before the
function description. The judge itself is unchanged and scores each
argument as before. In all main experiments, every judge keeps its usual
truncated input and reads the reference in addition (Appendix A).

## 5 Experiments

We ask whether DeRef improves every judge and how it compares with prior
ways to give the judge evidence (RQ1), where the gains come from (RQ2),
and whether the reference drives the judgment (RQ3).

### 5.1 Setup

#### Data and judges.

We use the three benchmarks of Section 3.2 and the two controlled sets
(Section 3.4 and Appendix A). Our main experiments run DeRef with four
of the seven judges: CLM, Jev, Qwen3-8B, and Qwen3.8-27B. Qwen3-8B is
the frozen backbone of CLM, so the two share one base model. Qwen3.8-27B
is the largest open LLM we run.

Inputs. Plain is the truncated input of Section 3.2. We compare DeRef
with three prior methods (Appendix G). ProvenanceGuard evidence gives
the judge snippets of the history that a model quotes as the source of
the proposed value (She et al., 2026). RevisEval gives the judge a
revised version of the proposed call (Zhang et al., 2025a). Both use
Qwen3.8-27B with the same settings as our deriver, and both see the
proposed value. Self-generated reference has the judge model write the
expected value from its own truncated input before it judges (Zeng et
al., 2024). It needs a judge that writes text, so it runs with Qwen3-8B
and Qwen3.8-27B. Full history has no window and no cut, up to about 32K
tokens (FCRB has no cut). We run it with Jev and the two LLM judges. We
report argument AUROC and $`\mathrm{Gap}_{\tau}`$ with $`\tau`$ set
again for each input. Appendix E gives call-level AUROC.

### 5.2 Main Results

DeRef improves every judge. Table 2 answers RQ1. It covers four judges
and three benchmarks, that is, 12 pairs of judge and benchmark. DeRef
raises argument AUROC over Plain in all 12 pairs, by between 1.44 and
22.14 points, and every gain is significant (Table 16 in Appendix H).
The Llama and Mistral judges gain between 8.78 and 20.84 points, also
significantly (Table 14 in Appendix G). The gains carry over to
call-level AUROC, where all 12 are again significant (Appendix E).

Comparison with prior methods. RevisEval is the strongest prior method
in all 12 pairs. DeRef is above it in 10 pairs and significantly above
it in 8. Averaged over the four judges, DeRef is significantly above
RevisEval on every benchmark (Appendix H). In the other two pairs,
Qwen3.8-27B on FCRB and FinTrace, RevisEval is higher by 0.32 and 0.27
points, and neither is significant. DeRef is significantly above
ProvenanceGuard evidence in all 12 pairs. Self-generated reference gains
at most 3.01 points over Plain and stays below DeRef in all six pairs
where it runs.

More context and more reasoning. Giving the judge the full history
instead of a reference is significantly below DeRef (Table 2). Averaged
over the three judges that are given it, the difference is 11.58 points
on CFB and 4.35 on FinTrace (Appendix H). More reasoning by the judge
does not make up for the reference either. Qwen3.8-27B judging directly
with thinking on stays below the same model reading the reference with
thinking off on all three benchmarks, by between 2.82 and 10.92 points
(Appendix G).

Controlled sets. On the buried version of FCRB-Relocate, where all four
judges fell to chance or below (Section 3.4), DeRef brings them back to
between 98.40 and 99.59 (Figure 2a). This includes CLM, which is not
given the full history. On the visible version and on FinTrace-HC, where
the judges were already accurate, DeRef makes no judge significantly
worse (Table 6 in Appendix A).

Table 3 removes one part of DeRef at a time. We show CFB with
Qwen3.8-27B because CFB has the largest gap on a single path and
includes sources that were cut from the judge input. Every drop is
significant, and the largest comes from writing the reference from the

Why keep the judge. Keeping only the parsed expected value costs little
where the reference states a value (1.39 points) and much where the
parser finds none (22.37 points), so the text beyond the stated value
helps mainly where it still carries the value (Appendix D). This is also
why we keep the judge instead of matching the candidate against the
parsed value: where the parser finds no value, a string match has
nothing to compare, and the judge still uses the rest of the reference.

Reference or more thinking. Table 4 crosses the reference with judge
thinking, with the full history in all four settings. The best setting
is the reference with thinking off, at 96.01. So the gain comes from the
reference, not from more reasoning by the judge.

Why hide the candidate. A deriver that sees the candidate, DeRef-v, is
above DeRef on CFB and below it on FCRB and FinTrace, and it names the
wrong value under test as the expected value up to six times as often
(Appendix G). We therefore keep the deriver that does not see the value.

### 5.4 Changing the Reference Changes the Judgment

Figure 3: Changing one value in the reference. Dots show the original
reference, which names the correct value. Arrow heads show it with a
wrong value from the same state.

We now test whether judges follow the DeRef reference itself. We take up
to 500 arguments per benchmark whose reference names the correct value
(332 on CFB, 417 on FCRB, and 500 on FinTrace). In the reference text,
we replace that value with a wrong value for the same argument from the
same state and keep all other text. On CFB and FCRB, where the wrong
values come from real models, all four judges follow the change
(Figure 3). At the 0.5 threshold, acceptance of correct values drops by
between 15.36 and 57.07 points, and acceptance of wrong values rises by
between 20.38 and 57.79 points. Argument AUROC falls from between 92.16
and 99.91 to between 42.63 and 77.92. All 24 changes are significant.
The swap also overturns judgments that agreed with the labels under
Plain. For correct values that a judge accepted with Plain input,
acceptance drops by between 10.85 and 53.62 points. For values labeled
wrong that it rejected, acceptance rises by between 11.00 and 50.74
points. FinTrace behaves differently, because we made its wrong values
by rule, and under Plain the judges accept at most 11.44% of them at
0.5. After the swap, their acceptance rises by at most 20.20 points, and
AUROC stays between 80.26 and 99.77. Still, CLM, Qwen3-8B, and
Qwen3.8-27B lower their acceptance of correct values by between 26.40
and 73.20 points, and Jev by 3.00 points. Since the reference is the
only text we change, the change in judgment comes from the reference
(examples in Appendix J).

Summary. RQ1: DeRef improves argument AUROC for every tested judge on
every benchmark and significantly outperforms RevisEval when averaged
over judges. RQ2: deriving a reference from the full history provides
gains that more context or judge thinking alone does not achieve. RQ3:
swapping the reference to name a wrong value can reverse judgments on
CFB and FCRB.

## 6 Conclusion

Argument judges tend to score the candidate against explicit reference
values in their input. When a correct value matches only a return that
was cut, or is a default with nothing saying that it applies, the input
holds no such reference, and judges of every type and size we test
accept it less often than a value shown in the input. On the two
multi-step benchmarks, the same holds for values that match no span of
the history. DeRef derives the reference from the full history before
the candidate is seen. Providing this reference improves overall
argument AUROC for all six judges we test on three benchmarks, with no
change to the judges, and substantially reduces the gap on cut returns
and on defaults.

## Limitations

Each argument has one gold value in our data, so a reference that names
it can lead judges to reject another value that is also correct
(Appendix A). On CFB and FinTrace, the wrong labels come from our own
construction, and an audit of 100 items per dataset by two annotators
could not confirm 3% and 4% of them. Appendix A runs a worst-case
analysis of this label uncertainty, and every gain of DeRef over Plain
remains significant. FCRB labels follow the official BFCL checker and
are not independently audited.

On FinTrace, DeRef does not shrink the gap on no-source values for three
of four judges (Table 17). The low base rate of this path may account
for part of that gap (Section 3.3).

Main results use one deriver model, Qwen3.8-27B, held fixed across
judges and input conditions. In the ablation (Table 3), a weaker
deriver, Qwen3-8B, still improves Qwen3.8-27B’s argument AUROC over
Plain on CFB. Broader evaluation of derivers from other model families
is left to future work.

Our judges include dedicated scoring models (CLM and Jev) and open LLMs
of up to 27B parameters, which show the pattern across judge types and
sizes. Evaluation on general-purpose frontier LLMs as judges is left to
future work.

## Ethical Considerations

We use three public benchmarks as released, together with public
trajectories of agent runs on ComplexFuncBench. Their requests ask for
function calls in tasks such as travel booking and financial queries,
and their tool returns hold data such as hotel listings and company
financials. We do not collect new data from people, and we do not try to
identify anyone. Names in the requests come from the benchmarks, and we
add no personal information. Two authors checked samples of labels and
paths by hand, and we used no crowd workers. Jev, which we reach through
an outside API, receives only benchmark text and model outputs.

Argument judges can gate tool calls that have real effects, such as a
booking or a trade. Our results show that judges follow the reference in
their input, and the swap test shows that a wrong reference overturns
many judgments. So a deriver that errs, or a tool return written to
mislead it, could make a judge accept a wrong argument. We therefore see
DeRef as support for review, not a replacement for it. Calls with high
stakes should still go to a person or to a check that does not rely on
the judge. We recommend keeping each derived reference with its scores,
so that a reviewer can see why a value was accepted.

The benchmarks are task-oriented, and their texts are function requests,
schemas, and tool returns. We did not see offensive content in the items
we read for our label and path checks. We did not screen every item, and
we use the texts as released.

## Appendix A Data and Judge Inputs

#### Choice of benchmarks.

We need three things: multi-step trajectories with real tool returns, so
that sources can be cut, a gold value for each argument, and wrong calls
made by real models. TRBench_BFCL uses the same BFCL tasks as FCRB in
its single-turn part and compares whole turns of calls in its multi-turn
part (Li et al., 2026b). The data of ProvenanceGuard label calls for
safety or judge tasks by their final outcome, so they give no gold value
per argument (She et al., 2026).

#### FCRB.

From the 1,500 single-turn requests of FC-RewardBench we drop the 15
with unparseable wrong outputs. We keep the 650 whose wrong call fails
the value check of BFCL (error type value_error). We then remove 20
whose only recorded message is a system prompt. We check each argument
of the wrong call on its own with the BFCL checker. It is labeled wrong
when the checker rejects its value and carries no label otherwise. This
leaves 630 requests, each with one correct and one wrong call, and 1,719
correct and 769 wrong argument values. FCRB has no earlier calls, so the
judge sees the request only.

#### CFB.

We use the released trajectories of 30 models on the 1,000 CFB tasks
(revision fcc906da). For each trajectory we find the first step where
the model call differs from the gold call. We keep the divergences in
which the model calls the gold function with different argument values,
since only these give an argument to label; a call to another function
or a missing call is left out. The gold history up to that step is the
state. The gold call is the correct call and the model call is the wrong
call. Models that make the same wrong call at a state are counted once,
so a state can carry several wrong calls. Parallel calls are matched to
gold calls by position. We drop 30 wrong argument values whose parallel
calls to the same function could not be matched in order. This leaves
347 correct and 644 wrong calls, with 1,639 correct and 999 wrong
argument values.

#### FinTrace.

FinTrace gives 800 test queries with golden trajectories (Cao et al.,
2026). It labels whole trajectories but no wrong calls at the argument
level. We make wrong calls from golden calls by rule, with a fixed seed
(20260930). Each wrong call keeps the endpoint and changes one argument.
A ticker becomes a ticker used in another query, a date or year moves by
one to three years (a from and to pair moves together), or the reporting
period switches between annual and quarter. We keep calls whose function
descriptions come from the documentation of the data provider, and we
drop 10 calls whose request has an unfilled template. This leaves 2,334
correct and 2,334 wrong calls, with 7,428 correct and 2,796 wrong
argument values.

#### Label checks and sensitivity analysis.

from each of CFB and FinTrace, without seeing any judge score or derived
reference. They agreed on 94% of the CFB items and 88% of the FinTrace
items, and settled the rest by discussion. Of 100 CFB arguments, 97 were
confirmed wrong, 2 could also be correct, and 1 was unclear. Of 100
FinTrace arguments, 96 were confirmed wrong, 2 could also be correct,
and 2 were unclear. We checked CFB and FinTrace because their argument
labels come from our construction procedures. FCRB labels follow the
official BFCL checker and were kept unchanged. To bound the effect of
these labels, we run a worst-case deletion (Table 5). For each judge and
dataset, we remove the share of wrong values that the audit could not

#### Judge input.

Every judge reads the same text (Figure 4). The state gives the request
and the most recent earlier calls with their returns. CFB shows the last
3 steps and FinTrace the last 5 calls of earlier turns. Each return is
cut to its first 1,000 characters. If the longest CLM input of a state
is still above 2,048 tokens, we drop the returns of the earliest shown
step, then whole early steps, and last the middle of the request,
keeping at least 40 tokens of it. A state that is still too long is left
out. Correct and wrong calls at a state share the state text. After the
state come the function line, the parameter line, and the proposed
value. On FCRB the parameter line adds the type, the enum, and the
default of the schema. On CFB it adds the enum, and on FinTrace it adds
nothing. The question to the judge is “Is this the correct value for
this parameter, given the question?” CLM is CLM-v0.1-8B. We call Jev
through OpenRouter with the version id typesafe/jev-1.13-20260917, and
we check that every reply returns this id. When we ask Jev again on 500
random inputs, 497 answers fall on the same side of 0.5 as before, and
scores differ by at most 0.17.

#### Reference block and extra truncation.

The reference goes after the state under the header “Expected value
(written before seeing the proposed value):”. If the state with this
block exceeds 2,048 CLM tokens, the state takes further steps of the
same ladder from its own level. This removes more early history for 131
of the 2,638 CFB arguments (39 states) and 786 of the 10,224 FinTrace
arguments (194 states). All four judges read the same DeRef input.

#### Full history.

The full-history input shows every earlier call and return, with no
window and no cut. On FinTrace, 248 of the 10,224 arguments have an
input longer than 32,768 tokens for a Qwen judge. For these we drop the
oldest returns, and then the oldest steps if needed, until the input
fits. No CFB input needs this. DeRef + full adds the reference to this
input and uses the same rule. Jev accepts less text (Table 11). For 104
FinTrace arguments with full history and 102 with DeRef + full, its
input drops one to three more of the oldest returns by the same rule.
Every other Jev input equals the Qwen input. Without these arguments, no
difference that involves the full history changes sign, and AUROC
differences move by at most 0.46 points.

#### FCRB-Relocate.

This set mirrors how history-only values arise in CFB: for 263 of its
279 correct history-only values (94.3%), the source return is in the
judge input but cut before the value. We start from FCRB correct values
that appear in the request. We move one such value into the return of an
added earlier call, find_saved_items, a name that no FCRB function uses.
The request is rewritten to point to the right entry by an attribute
that only this entry has. The return lists eight entries. One holds the
correct value. Seven distractors hold values of the same kind from other
FCRB samples, taken first from the same parameter name, then from the
same function, then from any parameter. In the visible version the
correct entry comes second. In the buried version it comes last. When
the correct entry would still start before character 1,000, every entry
in both versions gets the same filler note, repeated until the correct
entry of the buried version starts after that point, so the two versions
hold the same eight entries in a different order. In the buried returns,
the correct value starts between characters 1,009 and 1,201. The first
distractor (H) is in view in both versions and starts by character 33.
The wrong values are H for every state and, where one exists, a value
that appears in no text of the state (C). This gives 257 correct values
and 428 wrong values (257 H and 171 C) per version. We drop states in
which a distractor equals the correct value after lower-casing and
removing all characters other than letters and digits. Code asserts
every placement above. On the buried version, AUROC of the correct value
against H alone is 34.21 for CLM, 28.23 for Jev, 26.71 for Qwen3-8B, and
39.88 for Qwen3.8-27B. With the full history, the buried version reaches
99.81 \[99.65, 99.93\] for Jev, 98.39 \[97.54, 99.12\] for Qwen3-8B, and
99.86 \[99.65, 99.99\] for Qwen3.8-27B, as high as DeRef (Table 6). So
this set shows that judges fail when the source is out of view, not that
DeRef beats the full history. In a check of 19 states, the rewritten
request and the full return fix the correct value in all 19, and H is
wrong in all 19. Two of the 19 rewrites have wording problems that do
not change the label.

#### Revealing the source.

The test uses FinTrace correct history-only values whose first
occurrence was lost from the window. We exclude booleans, empty strings,
and numbers of at most two characters. We also exclude other numbers and
strings of at most three characters, which can match by chance. We keep
the 167 values whose source step lies outside the window (130 states, 93
queries). The reveal version inserts that step at its place in time. A
long return shows 1,000 characters centered on the value. The placebo
inserts another step of the same kind from outside the window of the
same trajectory. It does not contain the value and has the closest
displayed length. Both versions use the same header. The revealed step
is a return for 80 values, an earlier call of the agent for 82, and
assistant text for 5. Against the placebo, the source raises the mean
score of correct values by between 6.30 and 14.29 points for all four
judges, while wrong values in the same states move by at most 3.49
points. On revealed returns alone, the source raises correct scores
significantly for all four judges.

#### Schema facts.

For Figure 2b we add one line after the proposed value on every FCRB
argument whose schema has a default (1,037 items). The line restates the
default. It then quotes up to 40 characters around each check word found
in the request, or lists the check words when none is found. The check
words are the parameter name, the name with spaces for underscores, the
default value, and the enum values.

## Appendix B Derivation Path Census

We assign paths in this order, and the first match wins.

Visible: the value is found in the content of the Plain state, which is
the request, the shown calls, and the shown returns as cut. Template
text, the function and parameter lines, and the proposed value do not
count. History-only: the value is found in the full history, which is
the request and every earlier call and return, uncut. Format: the value
matches the request or a piece of the full history after one change. The
change can be lower-casing and collapsing whitespace, or reading both
sides as the same calendar date, the same number, or the same boolean.
Default: the value equals the schema default, or it is a “don’t care”
value that the parameter description names. No-source: none of the
above. A value is found when its text is a case-sensitive substring of
the search text. A number must not touch a letter, a digit, or a decimal
point, so 10 does not match 2010 or 10.5. A string shorter than four
characters must not touch a letter or a digit. A list is found when

## Appendix D Reading the Reference

Some analyses need the value that a reference states. They are the
ablation that keeps only the expected value, the swap test, and the
shares of references that name the correct value (Section 5.3). A
rule-based parser reads this value. It first removes Markdown emphasis.
It then matches a fixed set of sentence patterns, such as “should be”
followed by a value, and takes the value as a substring of the
reference. If no pattern matches, the reference counts as not fixing the
value. It also counts as not fixing the value when the same sentence
gives a second candidate value. This last rule changes 1, 22, and 51
argument slots on FCRB, CFB, and FinTrace. Parallel calls to one
function at a step share a slot, and the reference then lists the values
it expects, so these slots fall under this rule.

#### Checks.

We check the parser on samples drawn with seed 20260930, and no argument
is drawn twice. For each benchmark, a check reads 20 correct and 10
wrong arguments for which the parser finds a value, and asks whether
that value is the conclusion of the reference. We fixed the parser after
each failed round. In the fourth round, it took the right value for 30
of 30 arguments on every benchmark, so we accepted it. The parser can
also miss a stated value. So the first two rounds also read 20 correct
arguments per benchmark for which the parser found no value although the
reference text contains the correct value. In the second round, the
reference does state a value for some of them, so the parser misses a
small share of stated values. The last two rounds changed only one
fallback pattern and added the rule for a second candidate value. A miss
counts a stated value as not fixed, so the shares of references that
name the correct value can only be too low.

#### Parsed expected value only.

This ablation replaces the text of each reference block by one sentence.
When the parser finds a value, the sentence is “Expected value for
{name}: {value}.”, with the value copied from the reference. Otherwise
it is “The context does not determine the value of {name}.” Everything
else is the same as in DeRef, including the header of the block and its
place in the input. Table 8 splits the result by whether the parser
finds a value for the argument slot. Misses of the parser fall only into
the second group, so the first group does not depend on them. Where a
value is stated, the rest of the text adds 1.39 points on CFB, makes no
significant difference on FCRB, and costs 1.13 points on FinTrace. Where
no value is found, it adds 22.37 points on CFB and 3.67 points on
FinTrace. There the reference text still contains the correct value for
77.01% and 45.03% of the correct arguments.

## Appendix E Call-Level Results

Guards accept or reject a whole call (She et al., 2026), so we also
score each call from its argument scores. Process reward models combine
step scores by a product or a minimum (Lightman et al., 2024; Zhang et
al., 2025b), and the call score takes the minimum.

#### Call score.

For a call with argument scores $`s_{i}`$ and whole-call score $`w`$,
the call score is

```math
s_{\mathrm{call}}=\min\Big(w,\;\min_{i}s_{i}\Big), \tag{2}
```

The whole-call score always comes from the Plain input. Only the
argument scores change with the input. Most arguments of a wrong call
are not the changed one and carry no label. All but 134 of them have the
same judge input, word for word, as an argument of the correct call at
the same state, and they take that argument’s score under every input.
The other 134, all on FCRB, get their own score under every input.

#### Decomposed verification.

Fact checkers often split a text into atomic claims and verify each one
(Min et al., 2023). Atomic claims can lose the context needed to check
them (Gunjal and Durrett, 2024; Wanner et al., 2025), and splitting
helps weaker verifiers and can hurt stronger ones (Hu et al., 2025).
Process reward models also combine step scores, and the best rule
depends on how the step labels were made (Lightman et al., 2024; Zhang
et al., 2025b). An argument judge checks a call in the same way, one
argument at a time.

#### The gap costs at the call level.

Taking the minimum assumes that the weakest argument of a call is a
wrong one. A correct value out of view often breaks this assumption
(Table 10). Compared with the whole-call score alone, the minimum raises
call AUROC on FCRB, the dataset with the smallest gap, for every judge
by between 8.15 and 16.21 points. On CFB, which has the largest gap on a
single path, it adds nothing for any judge (from $`-3.04`$ to $`1.22`$
points, none significant).

## Appendix G Further Results

#### A wrong value from the history.

FinTrace-HC pairs two wrong values for the same argument in the same
state, one that appeared earlier in the history (H) and one that did not
(C). On the 106 pairs in which both values exist, the mean score of H
minus C is 7.79 \[5.08, 10.39\] for CLM, 5.06 \[3.08, 7.36\] for Jev,
3.79 \[0.88, 7.53\] for Qwen3-8B, and 0.72 \[$`-`$0.08, 2.01\] for
Qwen3.8-27B, with query-clustered bootstrap CIs; the first three are
significant.

#### The reference on top of the full history.

On CFB, DeRef with the full history reaches 84.97 for Qwen3-8B and 96.01
for Qwen3.8-27B. It beats the full history alone by 18.04 and 10.56
points, and DeRef on the truncated input by 1.84 and 0.92 points. Its
largest gain over the full history is on no-source values, 32.87 and
18.87 points. On FinTrace, it reaches 91.94 and 92.52, and it beats the
full history alone by 7.20 and 2.75 points. For Jev, it beats the full
history alone by 9.35 points on CFB and 3.18 on FinTrace.

#### A deriver that sees the value.

DeRef-v tests the choice of a deriver that does not see the candidate.
Its deriver gets the DeRef prompt with the candidate value added and the
opening words “Before seeing any proposed value:” removed. Everything
else is the same, including the header of the reference block, which
still says that the reference was written before seeing the proposed
value. We keep this header so that the judge input changes only through
the reference itself. Its references differ in length from those of
DeRef, so 152 CFB inputs and 212 FinTrace inputs keep a different amount
of early history within 2,048 tokens.

#### Deriver prompt.

When a step calls the same function more than once, the deriver names
each value it expects, such as the two hotel IDs that a request for the
two cheapest hotels asks for. The deriver gets the system prompt “You
are a careful evaluator of tool calls made by an AI assistant.” Its user
message gives the request, every earlier call and return uncut under the
header “History (all earlier calls and their returns, oldest first):”,
and the function and parameter lines of the call under judgment. It ends
with this instruction: “Before seeing any proposed value: what should
the value of parameter {name} be in this call, and where in the context
does it come from? Quote the source text if there is one, or say that
the context does not determine it. Answer in at most 3 sentences.” The
message contains no value of the call under judgment and no other
candidate at that step.

#### Snippet rule.

For a candidate value, we search the full history for every place where
it occurs and cut a snippet of 150 characters on each side of each
occurrence; nearby windows are merged, a merged snippet is cut to 450
characters, and at most three snippets are kept, most recent first. The
test of Section 3.4 adds these snippets to the judge input on CFB.

#### ProvenanceGuard evidence.

ProvenanceGuard checks a proposed call in stages, and its provenance
stage asks an LLM to find, for each derivable parameter value, the
evidence in the user query or earlier tool outputs that supports it (She
et al., 2026). ProvenanceGuard then labels the call misaligned when no
evidence is found. We keep the provenance stage and hand its evidence to
the judge, so that the judge returns a score. Qwen3.8-27B sees the
proposed value and quotes up to two passages that the value should come
from. It runs with thinking on, and we take the quotes from the text
after the thinking. A quote counts when it matches a piece of the full
history, exactly or by a long common substring. On FinTrace and FCRB,
the snippets around the quotes follow the snippet rule above. On CFB, it
uses windows of 100 characters on each side without a length cap. An
argument without a snippet keeps its Plain score.

#### Revised calls.

RevisEval revises the proposed call from the full history, one revised
call per proposed call, and the judge reads the revised call (Zhang et
al., 2025a).

## Appendix I Extended Related Work

This appendix expands the related work of Section 2.

#### Judges for tool-calling.

Tool-call benchmarks check calls against gold answers. BFCL matches each
argument value against a set of allowed answers (Patil et al., 2025),
and ComplexFuncBench judges a whole call with rules, response matching,
and an LLM (Zhong et al., 2025). Without gold answers, learned judges
score or compare whole calls (Agarwal et al., 2025; Li et al., 2026b) or
score each argument as a step (Lin et al., 2026). ToolPRMBench and
AgentProcessBench evaluate step-level judges for tool-using agents, and
the latter finds that judges tend to label steps as correct (Li et al.,
2026a; Fan et al., 2026b). AgentJudgeBench finds that LLM judges of tool
calls agree less with a programmatic reference as tasks get harder
(Verma et al., 2026). Guards check calls before they run.
ProvenanceGuard has an LLM find evidence for each derivable argument
with the value in hand, and later, without the proposed action, check
whether more than one action fits the context (She et al., 2026). PACT
tracks where each argument value came from (Fan et al., 2026a). In
Agent-Sentry, the agent reports whether each value is copied verbatim,
derived, or generated (Sequeira et al., 2026). When rules flag a
suspected failure in a proposed call, TwinCheck repairs it or writes a
constrained alternative from the trace and the flagged evidence, and a
verifier compares the two (Dai and Huang, 2026). Jev trails GPT-6 where
the verdict has to be derived rather than read off the text (Li et al.,
2026c), and factuality metrics drop on summaries that need deeper
reasoning to check (Ramprasad and Wallace, 2025). To our knowledge, none
of these studies splits judge errors by derivation path.

#### Reference-guided judging.

Judges grade better with a reference answer. In MT-Bench, the judge
first answers a math question without seeing the answers under review,
then grades against its own answer, which reduces its errors (Zheng et
al., 2023). LLMBar and the candidate-blind head of BAER also have the
judge write its own output first (Zeng et al., 2024; Li et al., 2026d),
and RevisEval builds the reference by revising the candidate (Zhang et
al., 2025a). Without a reference, judges agree less with experts
(Krumdick et al., 2025) and give credit to wrong answers (Chalamalasetti
and Vajjala, 2026). On math and code, judges without a reference reward
wrong answers that look convincing, and a judge that commits to its own
solution before grading accepts far fewer of them (Zhou, 2026). SGV
finds that verifiers of agent trajectories tend to agree with the
candidate, and it first writes priors without the candidate (Andrade et
al., 2026). MARCH and factored Chain-of-Verification also check claims
without showing the checker the answer under test (Li et al., 2026e;
Dhuliawala et al., 2024). For code agents, an agent explores the
repository and writes a rubric before scoring any patch (Raghavendra et
al., 2026). When a QA reference is swapped for a wrong one, judges often
reject answers that match it, which the authors trace to the judges’ own
knowledge (Lee et al., 2026). These judges write the reference from the
question and their own knowledge, which is often not enough for an
argument judge, whose expected value can sit in a tool return cut from
its input. A reference that the judge writes from its own input, as in
LLMBar, improves on Plain input by at most 3.01 points but stays below
DeRef (Section 5.2); writing the DeRef reference from the cut input
instead of the full history alone costs 9.63 points on CFB (Table 3),
and on CFB and FCRB our judges follow a swapped reference (Section 5.4).

#### Correct content without support.

A value without support in the context is not always wrong. Many
entities that summarizers add without support are still factual (Cao et
al., 2022). RAG models also often answer correctly when the context is
insufficient (Joren et al., 2025). Models also score an inconsistent
summary higher when its text is copied from the source (Tam et al.,
2023). Tool-call arguments make this common, since a correct default,
format change, or inferred value has no matching span in the dialogue.
We do not treat such values as errors, and we measure how often judges
do. A source in the context can also go unused. Models miss facts that
share few words with the question (Modarressi et al., 2025), and they do
worse as tool returns grow longer (Kate et al., 2025).

Figures 5 and 6 show two arguments, one for each of two findings.

argument at random from those that meet it, with seed 20260930. A script
copies all text from the judge inputs and the deriver outputs. The
excerpts show the lines relevant to the argument, and as in Figure 4 we
write the long dash after a function or parameter name as --. Scores are
each judge’s probability that the value is correct.

#### A default.

In Figure 5, the request asks for the details of Adriel’s internships
and names no organization. The correct value of
experience_or_education_name is the schema default, “Not specified”,
which the parameter line states. With Plain input and with the
schema-facts line, all four judges score it below their thresholds
$`\tau`$. The DeRef reference says that the request names no
organization, so the parameter should take its default. With it, CLM,
Jev, and Qwen3.8-27B score the value above their thresholds, and
Qwen3-8B scores it at its threshold of 1.0000, which counts as accepted
only with the tie fraction $`q`$ (Appendix C). The condition is this
pattern for all four judges. One of the 142 arguments of Figure 2b meets
it.

#### A swapped reference.

In Figure 6, the request asks for an alarm at 5 in the afternoon. The
correct value of new_alarm_time is 17:00, and the wrong FCRB call, made
by a real model, uses 15:00. The original reference names 17:00, and the
swapped reference changes only that value. With the original reference,
all four judges score the correct value at or above 0.5 and the wrong
value below 0.5. With the swapped reference, all four judges reverse
both judgments. Under Plain input, CLM and Qwen3-8B score both values at
or above 0.5, Jev scores only the correct value above 0.5, and
Qwen3.8-27B scores only the wrong value above 0.5. The condition is that
all four judges reverse both judgments at 0.5. Of the 749 CFB and FCRB
arguments in the swap test, 14 meet it. We exclude the two pairs whose
values differ only by a power of ten, 5.0 against 0.05 and 16 against
1600, since the schema leaves their unit open, and draw from the
remaining 12.
