# A Better LLM Evaluator for Text Generation: The Impact of Prompt Output Sequencing and Optimization

KuanChao Chu^(\*)    Yi-Pei Chen^(\*)    Hideki Nakayama

###### Abstract

This research investigates prompt designs of evaluating generated texts
using large language models (LLMs). While LLMs are increasingly used for
scoring various inputs, creating effective prompts for open-ended text
evaluation remains challenging due to model sensitivity and subjectivity
in evaluation of text generation. Our study experimented with different
prompt structures, altering the sequence of output instructions and
including explanatory reasons. We found that the order of presenting
reasons and scores significantly influences LLMs’ scoring, with a
different level of rule understanding in the prompt. An additional
optimization may enhance scoring alignment if sufficient data is
available. This insight is crucial for improving the accuracy and
consistency of LLM-based evaluations.

## 1. Introduction

^(†)^(†)footnotetext: Equal contribution

Using large language models (LLMs) \[1, 2\] as evaluators to assign
scores to the given inputs have become prevalent. Leblond et al. \[3\]
outputs a score between 0 and 1 to estimate the correctness of generated
code, thereby automatically ranking its quality. Similarly, Park et al.
\[4\] assign poignancy score to the generated text for the retrieval
task. Other research explores using LLMs to assess generated texts,
finding the LLM scores correlates higher with human evaluators than
existing automatic metrics \[5, 6, 7, 8\].

However, designing evaluation prompt for LLMs is not a trivial task,
especially for dialogue evaluation. Different models exhibit varied
sensitivity to the nuances of input prompts. Even slight linguistic
variations can lead to significant fluctuations in task performance
\[9\]. Moreover, the inherent subjectivity in dialogue evaluation adds
on the difficulty and versatility in LLMs’ evaluation results. While
prompt optimization techniques \[10, 11, 12, 13\] have been developed to
assist in designing more effective prompts, these methods require paired
input-output samples for objective value calculation. Unfortunately, the
lack of available dialogue-score pairing data hampers the application of
prompt optimization in dialogue evaluation.

In this study, we aim to investigate the influence of prompt design on
dialogue evaluation, specifically focusing on how the output
instructions affects the resulting scores. We have developed multiple
prompt variations to assess the quality of a series of dialogues. These
variations involve altering the sequence order of the outputs and
examining whether including explanatory reasons along with the scores
impacts the evaluation. Our analysis compares the influence of different
prompts on the scoring outcomes across various versions of GPT models.

Figure 1: Score distribution across 50 trials for each model and output
instruction configuration for a dialogue set.

We observed that the different order of output instructions can result
in different scoring distributions by certain LLMs, even when the
corresponding output reasons are similar. Considering the sequential
generation nature of auto-regressive models, placing the score after the
reasons allows it to reference both the reasons and the input prompt, a
dynamic not possible when this order is reversed. The finding suggests
that a “reason-first” output instruction might lead to a more
comprehensive understanding and adherence to the specific requirements
of the task.

Finally, we further investigate the effect of prompt optimization on the
“reason-first” output instruction. This is to observe the most effective
form of instruction in a hypothetical setting where paired data is
available.

#### Approach

In this section, the task assigned to the LLM is to rate a given set of
dialogues on a scale from 1 to 10, where 1 indicates no issues in the
set of dialogues, and 10 signifies severe problems. Additionally, if
specified in the prompt, the LLM is required to provide a rationale for
the rating. The dialogues are presented in chronological order, and the
output score is determined based on a comprehensive evaluation of the
entire set, focusing on key aspects such as factual accuracy,
repetitiveness, and coherence.

Along with the task description, we have integrated five customized
rules into the prompt, derived from observations in previous experiments
without these rules. The special rules include instructions for the LLM
to prioritize the number of issues over their impact and to assign more
weight to aspects exhibiting significant issues, rather than averaging
out the score across all aspects.

The final evaluation prompt is organized as follows: a set of dialogues,
task description, special rules, and output instruction (see Table 1).
For each set of dialogues, we conducted $`N`$ trials for each of the six
configurations (config), varying the output instruction. This experiment
was then replicated across $`M`$ different models.

Figure 3: Score distribution across 50 trials for each model and output

#### Data

To assess the capability of LLMs in identifying issues within dialogues,
we collected LLM-generated dialogues from Park et al. \[4\] and manually
grouped them into 25 sets. Each set contains four to six dialogues and
exhibits one or more problems, such as repetition or contradictions
between dialogues.

#### Model

We selected four recent LLMs to serve as scorers: gpt-3.5-turbo-0613,
gpt-3.5-turbo-1106, gpt-4-0613, and gpt-4-1106-preview (gpt-4-1106).
Note that our aim is to analyze the evaluation scores across various
models when altering output instructions, and not to compare them with
human judgements for this task.

#### The Importance of Output Instruction Order

Table 2 presents the mean scores and standard deviations (std) of 10
trials for all 25 dialogue sets across all configs and models. In both
ex ($`\cdot`$) and json ($`\cdot`$) formats, the mean scores for the rs
settings (output reasons before the score) are generally higher than
their sr (output score before reasons) counterparts. ¹¹ 1 The exception
is observed with the gpt-4-1106 model.For instance, in the json (rs)
config using gpt-4-0613, the mean score is 5.34, while it drops to 3.26
in json (sr), despite providing similar reasons. We conjecture that in
the rs setting, the autoregressive nature of the model allows the score
to be influenced by the previously outputted reasons.

In a focused study on a single set with additional 40 trials, as

and the distinctions between different settings became less pronounced.
This highlights the models’ sensitivity to the changes of the prompt.

## 3. Prompt optimization

#### Approach

We assume there are sufficient paired input and output data samples for
the scoring task. Hence, in this section, we examine how output
instructions can be enhanced through additional prompt optimization. We
apply two recent optimization methods to the existing prompt: GRIPS
\[13\] and OPRO \[11\]. For a given score set $`\mathcal{S}`$ (i.e.,
input and output data pairs), GRIPS iteratively searches for a chain of
editing commands to maximize the overall score on $`\mathcal{S}`$.
Meanwhile, OPRO directly employs a LLM as an optimizer to generate new
prompts, with previous score trajectories included as part of the
reference material for the optimizer. Specifically, we utilize the json
(rs) style for the output instruction in the initial prompt, optimizing
only the output instruction section while keeping the other sections
unchanged.

#### Data and Implementation Details

For this experiment, we utilize SummEval \[14\], which comprises 1,600
text summarization samples derived from 100 unique document pieces and
16 summarization models. Each sample includes human expert ratings
ranging from 1 to 5 across various aspects. We focus on the ”coherence”
aspect for the expected output. To ensure rating diversity in
$`\mathcal{S}`$, we uniformly sample 10% of the documents after ranking
them by their average coherence score to create the score set for GRIPS,
and use a halved subset for OPRO. The remaining 90% of the data is
reserved for testing.

For GRIPS, we configure the editing operations at the word level and
conduct 10 search iterations, with 5 candidates in each iteration. For
OPRO, we employ gpt-4-0613 as the optimizer, running 50 iterations with
2 generations each. We include two randomly selected data exemplars from
$`\mathcal{S}`$ when generating the output instructions.

We calculate the mean absolute error (MAE) between the human ratings and
LLM ratings to evaluate the overall score for $`\mathcal{S}`$.
Furthermore, an additional entropy term is introduced for the binned
output predictions to enhance output diversity, as suggested in the
original paper, with a coefficient of $`0.25`$. Consistent with default
settings, we linearly rescaled the score to a 0 to 100 rating scale for
OPRO, and inverted the sign for GRIPS. All the methods utilize
gpt-3.5-turbo-0613 for generating LLM scorer outputs. In the score set,
the temperature was set to $`0.3`$, and a rating is averaged over 10
trials. In the test set, we set the temperature to $`1.0`$, with the
number of trials increased to 20.

### 3.1 Result and Analysis

#### The Changes in Output Instructions and Generalization on Test Data

In the prompt examples shown in Table 3, OPRO demonstrates a preference
for developing a diverse and detailed output instruction section. Some
of the content either repeats or adds new details to the grading policy
and may explicitly request the provision of reasons. The changes made
using GRIPS, however, are comparatively limited due to the smaller
search space. For example, the candidate with the best score on
$`\mathcal{S}`$ underwent only five editing commands:
“del-del-swap-swap-del.”

Table 4 lists the performance of the LLM scorer on the test set.
Surprisingly, the output instruction modified with GRIPS yield improved
scores, whereas OPRO shows the opposite. However, the number of
iterations set for OPRO is fewer than what was used in the original
paper, due to cost constraints. Therefore, its performance might be far
from saturation. Following \[15\], we apply William’s test to Pearson’s
r, and we found that the improvement with GRIPS over the initial
instruction is statistically significant.

#### The Score Difference for Swapped Orders Exists

We also compare the json (rs) and json (sr) types of initial
instructions. The averaged score on the test set is 3.656 for json (rs)
and 3.270 for json (sr). This reflects a similar distribution difference
to what we observed in the previous section.

#### Challenges

First, although we intentionally divide a score set to study the effect
of optimization, collecting related samples for a specific scoring task
can be challenging. Second, these optimizations are applied globally to
all data samples, while the optimized output instructions might vary for
individual cases. Finally, the optimized instructions could break the
structured output format and thus requires careful post-generation
processing.

## 4. Conclusion

Our study highlights the scoring sensitivity of LLMs to the order of
output instructions, which can be amplified by task-specific rules.
Users should verify that their intentions align with the outputs using
crafted prompts. Additionally, prompt optimization has proven beneficial
in aligning LLM outputs with ground-truth scores, emphasizing the need
for sufficient data samples for arbitrary scoring tasks. These findings
offer insights for designing prompts in subjective tasks like dialogue
evaluation.
